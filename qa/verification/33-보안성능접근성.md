# 보안성능접근성 코드검증

- 범위: ALH-0842 ~ ALH-0865 (24건)
- 대상: `back/src/main/java/com/allohub/global/config/WebConfig.java`, `GlobalExceptionHandler.java`, `application.yml`, `front/src/pages/ScreenPage.tsx`, `ResultPage.tsx`, `AllocatePage.tsx`, `front/src/api/api.ts`, `front/nginx.conf`, `ai/src/llm/explainer.py`, `ai/src/scoring/company.py`
- 방법: 케이스는 모두 `WebConfig.java`를 가리킨다. 그 파일은 `/api/**` CORS 허용 출처와 RestTemplate 3초/40초뿐이다. 나머지는 실제 계층을 보고, 그 파일이 구현하지 않으면 근거에 적었다. 브라우저·부하 도구는 실행하지 않았다.
- 판정: 통과 9, 실패 5, 부분 10, 확인불가 0

## 실패·부분

- ALH-0842 부분. 화면 하단과 기본 설명은 참고값이라고 말한다. Gemini 본문의 투자 권유를 지우는 코드는 없고, RAG 정화는 부도·파산 문구만 바꾼다. `WebConfig.java`는 이 차단을 하지 않는다.
- ALH-0848 실패. Spring Security가 없고 `GET /api/allocations`는 인증 없이 최근 배분과 출자자 이름을 돌려준다. 인증이 필요한지에 대한 결정도 코드에 없다.
- ALH-0849 부분. `POST /api/v1/disclosure/explain|search|evaluate`에 인증과 요청 제한이 없다. compose가 AI를 `127.0.0.1:8000`에만 묶을 뿐이다. `WebConfig.java`는 이 경로를 다루지 않는다.
- ALH-0850 실패. 초당 100건의 오류율·응답시간을 재는 코드, 제한, CI 부하 테스트가 없다.
- ALH-0853 부분. 최근 10건은 `findTop10ByOrderByIdDesc`라 PK 순이다. 슬로우 쿼리 로그나 실행 계획 점검은 없다.
- ALH-0854 부분. `index.html`에 viewport는 있다. 출자자 행이 `grid-cols-[1fr_120px_auto]`라 320px에서 입력과 삭제 버튼이 가로로 넘칠 수 있다. 줄바꿈용 미디어쿼리는 없다.
- ALH-0855 부분. 입력과 버튼은 네이티브 요소라 Tab으로 도달하고, 포커스된 버튼은 Enter로 눌린다. `form`이 없고 버튼이 `type="button"`이라 입력 중 Enter로는 진단·배분이 나가지 않는다.
- ALH-0858 실패. 오류는 빨간 `p` 텍스트다. `role="alert"`나 `aria-live`가 없어 나타난 오류를 스크린리더에 알리지 않는다.
- ALH-0859 부분. 결과 제목과 오류에 `overflow-wrap`이 없다. 한글 100자는 보통 줄바꿈되지만, 조회 결과 제목은 사용자가 친 100자가 아니라 표의 종목명이다.
- ALH-0860 실패. `front/src/api/api.ts`의 `fetch`에 timeout이나 `AbortSignal`이 없다. 응답 전까지 `진단 중...`이 유지된다. nginx `proxy_read_timeout`은 60초이고, WebConfig의 40초는 AI 호출용이다.
- ALH-0861 실패. 동시 20요청의 P95나 자원 사용을 기록하는 코드가 없다.
- ALH-0862 부분. AI 결과는 `bas_dt`를 만들지만 `CompanyScreen`과 결과 화면은 기준일을 저장하거나 보여 주지 않는다. 데이터 범위 고지도 없다.
- ALH-0863 부분. 하단 고지와 기본 설명은 참고값이라고 한다. 양성 비율, F1, 점수 불확실성은 화면과 API에 없다. README에만 약 8% 언급이 있다.
- ALH-0864 부분. 현재 오류 문장에는 출자자 이름이 들어가지 않는다. 이름을 마스킹하는 로그 정책은 없고, 이름은 DB와 `GET /api/allocations`에 평문이다.
- ALH-0865 부분. Vite 빌드 JS는 파일명에 해시가 붙는다. `nginx.conf`는 `index.html`에 `Cache-Control: no-cache`를 주지 않아 HTML이 남으면 옛 번들이 유지된다. `WebConfig.java`는 정적 캐시를 설정하지 않는다.

## 전체 결과

| ID | 우선순위 | 항목 | 판정 | 근거 |
| --- | --- | --- | --- | --- |
| ALH-0842 | P1 | 공시 근거 없는 투자 확정 | 부분 | `App.tsx` 하단과 `basic_explanation`은 투자 권유가 아닌 참고값이다. 메인 경로 `explainer.explain`은 Gemini 문장을 그대로 반환한다. `sanitize_risk_statements`는 투자 권유 문장을 삭제하지 않는다. |
| ALH-0843 | P1 | 기업명 XSS | 통과 | `WebConfig.java`는 XSS를 처리하지 않는다. 결과의 `companyName`과 오류는 React 텍스트다. `dangerouslySetInnerHTML`이 없어 `<img onerror>`는 스크립트로 실행되지 않는다. |
| ALH-0844 | P1 | 출자자 이름 XSS | 통과 | 출자자 이름은 `AllocatePage`에서 `{line.investorName}` 텍스트로 그린다. `<script>`는 실행되지 않고 문자열로 남는다. 백엔드 설정 파일은 이 출력과 무관하다. |
| ALH-0845 | P1 | SQL injection | 통과 | 종목 검색은 `company.py`의 pandas `str.contains(..., regex=False)`다. Spring 조회는 `findById`, `findTop10ByOrderByIdDesc`뿐이고 회사명을 붙인 native query가 없다. pgvector SQL은 `%s` 바인딩이다. |
| ALH-0846 | P1 | API 민감정보 | 통과 | `WebConfig.java`가 아니라 `GlobalExceptionHandler`다. 예상 밖 예외의 본문은 `서버 오류가 발생했습니다.`이고 스택과 환경변수는 JSON에 넣지 않는다. 5xx `ApiException`도 고정된 서비스 문장만 돌려준다. |
| ALH-0847 | P1 | CORS 비허용 | 통과 | 이 항목만 `WebConfig.addCorsMappings`가 구현한다. 허용 출처는 `application.yml`의 Vite `5173`~`5175`다. Spring 6.1은 그 목록에 없는 `attacker.example`을 403 `Invalid CORS request`로 거절한다. |
| ALH-0848 | P1 | 정보 무단 조회 | 실패 | `build.gradle`에 security 스타터가 없다. `AllocationController`의 목록·단건 조회는 누구나 호출한다. 요구사항으로 인증 여부를 정한 설정이 없다. |
| ALH-0849 | P1 | 관리자 API 접근 | 부분 | 공시 RAG 라우터에 인증 의존성이나 속도 제한이 없다. 배포에서 AI 포트만 루프백으로 제한된다. |
| ALH-0850 | P1 | 대량 요청 | 실패 | 측정 엔드포인트, 레이트 리밋, 부하 잡이 없다. `WebConfig.java`에도 없다. |
| ALH-0851 | P1 | 동시 배분 | 통과 | `AllocationCalculator.split`은 지역 변수만 쓰고, ID는 DB identity다. 같은 요청 10번은 레코드 10개이며 금액이 서로 섞일 공유 상태가 없다. 동시 호출 실험은 하지 않았다. |
| ALH-0852 | P1 | 외부 API 느림 | 통과 | `GEMINI_TIMEOUT_MS`는 15000이다. `explainer.py`는 예외나 빈 응답이면 `basic` 설명을 반환한다. WebConfig의 읽기 40초는 그 폴백을 만들지 않고, 폴백 이후에도 Spring이 끊지 않게 하는 상한이다. |
| ALH-0853 | P1 | DB Slow Query | 부분 | 최근 10건 쿼리는 PK 내림차순이다. 추가 인덱스와 느린 쿼리 점검 설정은 `application.yml`과 `WebConfig.java` 모두에 없다. |
| ALH-0854 | P1 | 반응형 모바일 | 부분 | viewport와 `max-w-3xl`은 있다. 320px에서 출자 입력 그리드의 120px 고정 열이 넘침을 막지 못한다. |
| ALH-0855 | P1 | 키보드 접근성 | 부분 | 키보드로 버튼까지 이동해 실행할 수는 있다. 필드에서 Enter로 제출되지는 않는다. |
| ALH-0856 | P1 | 라벨 연결 | 통과 | `WebConfig.java`와 무관하다. `ScreenPage`와 `AllocatePage`가 `label` 안에 `input`을 넣어 스크린리더 이름이 된다. `htmlFor`는 없다. |
| ALH-0857 | P1 | 위험 등급 색맹 | 통과 | `gradeLabel`이 `stable`/`warning`/`danger`를 `안정`/`주의`/`위험` 글자로 보여주고 점수도 같이 쓴다. 색 클래스만으로 구분하지 않는다. |
| ALH-0858 | P1 | 에러 메시지 접근성 | 실패 | 오류 단락에 라이브 리전이나 alert 역할이 없다. 색과 문장만 바뀐다. |
| ALH-0859 | P1 | 장문 회사명 | 부분 | 입력칸은 `w-full`이라 페이지 폭을 밀지는 않는다. 긴 문자열용 줄바꿈 강제는 없고, 결과 `h2`는 저장 종목명을 보여 준다. |

| ALH-0861 | P1 | 모델 예측 응답시간 | 실패 | 추론 시간 히스토그램, P95, 자원 관측 코드가 없다. |
