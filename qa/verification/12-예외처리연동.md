# 예외처리연동 코드검증

- 범위: ALH-0358 ~ ALH-0377 (20건)
- 대상: 인용 파일은 `AiClient`다. 예외 본문은 `GlobalExceptionHandler`·`ApiException`, CORS·타임아웃은 `WebConfig`·`application.yml`, 프록시는 `front/nginx.conf`, snake_case 변환은 `ScreenService`·`AllocationService`다.
- 방법: 소스 대조. Jackson 2.15.4에서 JSON `null`과 누락 필드의 `asDouble()`만 따로 확인했다. 모의 FastAPI는 띄우지 않았다.
- 판정: 통과 16, 실패 4, 부분 0, 확인불가 0

## 실패·부분

- ALH-0359 실패. HTTP 본문 JSON `null`은 Java null이 아니라 `NullNode`다. `AiClient`의 `response == null`에 걸리지 않아 `AI_ERROR`가 아니다.
- ALH-0362 실패. 404만 따로 둔다. FastAPI 422는 502 `AI_ERROR`이고 `detail`은 버려진다. 검증 계층으로 매핑되지 않는다.
- ALH-0368 실패. `score`가 없으면 `MissingNode.asDouble()`이 0.0이다. `ScreenService`·`AllocationService`는 그 값을 그대로 저장한다.
- ALH-0369 실패. `"score": null`은 `NullNode`이고 `asDouble()`이 0.0이다. null을 거절하지 않는다.

| ALH-0358 | P1 | AI 정상 응답 | 통과 | `AiClient.screen`이 `postForObject(..., JsonNode.class)` 결과를 그대로 반환한다. 200 JSON 객체는 `JsonNode`다. |
| ALH-0359 | P1 | AI 응답 null | 실패 | JSON `null`은 `NullNode`라 null 검사가 실패하지 않는다. 이후 `path().asDouble()`이 0점으로 저장될 수 있다. |
| ALH-0360 | P1 | AI 404 JSON detail | 통과 | 상태 404만 `readDetail`로 간다. `detail`이 문자열이면 그 문장으로 `ApiException.notFound`를 던져 404에 실어 보낸다. |
| ALH-0361 | P1 | AI 404 문자열 | 통과 | 본문 파싱이 실패하면 `readDetail`이 `"상장 종목에서 회사를 찾지 못했습니다."`를 반환한다. 상태만 404다. |
| ALH-0362 | P1 | AI 422 유효성 | 실패 | 422는 `HttpStatusCodeException`의 일반 분기다. 502 `AI_ERROR`와 고정 문구만 나가고 FastAPI `detail`은 전달되지 않는다. |
| ALH-0363 | P1 | AI 503 | 통과 | 503도 404가 아니면 `ApiException.aiError`다. 응답 `errorCode`는 `AI_ERROR`다. HTTP 상태는 503이 아니라 502다. |
| ALH-0364 | P1 | AI 응답 지연 | 통과 | `WebConfig`의 `RestTemplate` read timeout이 40초, connect timeout이 3초다. 초과는 `RestClientException` → 502 `AI_ERROR`라 무한 대기하지 않는다. |
| ALH-0365 | P1 | AI 연결 거부 | 통과 | 기본 `app.ai.base-url`은 `http://localhost:8000`이다. 연결 거부는 `RestClientException`이라 `AI_ERROR`다. |
| ALH-0366 | P1 | AI 주소 DNS 오류 | 통과 | `UnknownHostException`도 같은 `RestClientException` 분기로 `AI_ERROR`다. 502는 5xx라 `GlobalExceptionHandler`가 cause를 error 로그로 남긴다. |
| ALH-0367 | P1 | AI 잘못된 JSON | 통과 | 200이어도 `{invalid` 변환 실패는 `RestClientException`으로 감싸진다. `AiClient`가 502 `AI_ERROR`로 바꾸고 핸들러가 그 5xx를 반환한다. |
| ALH-0368 | P1 | AI 데이터 일부 누락 | 실패 | 없는 `score`는 `asDouble()` 0.0이다. 필수 필드 검사가 없어 0점 진단이 저장된다. |
| ALH-0369 | P1 | AI 결과 score=null | 실패 | JSON null도 `asDouble()` 0.0이다. 0점과 구분하지 않고 저장한다. |
| ALH-0370 | P1 | API 핸들러 VALIDATION_ERROR | 통과 | 인용 파일은 `AiClient`가 아니다. `MethodArgumentNotValidException`을 `GlobalExceptionHandler`가 400 `VALIDATION_ERROR`와 `필드: 메시지`로 바꾼다. |
| ALH-0371 | P1 | API 핸들러 INVALID_JSON | 통과 | 요청 본문이 파손되면 `HttpMessageNotReadableException` → 400 `INVALID_JSON`이다. |
| ALH-0372 | P1 | API 핸들러 INTERNAL_ERROR | 통과 | 그 외 `Exception`은 500 `INTERNAL_ERROR`와 `"서버 오류가 발생했습니다."`만 반환한다. 예외 메시지는 로그에만 남는다. |
| ALH-0373 | P1 | CORS 허용 개발 origin | 통과 | `application.yml`의 `app.cors.allowed-origins`에 `http://localhost:5173`이 있다. `WebConfig`가 `/api/**`에 그 origin과 `GET`,`POST`,`OPTIONS`를 허용한다. preflight에 `Access-Control-Allow-Origin`이 나간다. |
| ALH-0374 | P1 | CORS 거부 임의 origin | 통과 | 허용 목록이 고정 origin이다. `https://evil.example`은 일치하지 않아 `Access-Control-Allow-Origin`을 붙이지 않는다. |
| ALH-0375 | P1 | Content-Type application/json | 통과 | 컨트롤러가 `@RequestBody`를 쓰고 `spring-boot-starter-web`의 Jackson 컨버터가 `application/json`을 역직렬화한다. |
| ALH-0376 | P1 | 프록시 /api 연동 | 통과 | `front/nginx.conf`의 `location /api/`가 `proxy_pass http://back:8080`이다. URI를 바꾸지 않아 `/api/screens`가 Spring으로 전달된다. `AiClient` 경로가 아니다. |
| ALH-0377 | P1 | AI 스키마 snake_case | 통과 | `ScreenService`와 `AllocationService`가 `Map.of("company_name", name.trim())`을 `AiClient`에 넘긴다. Map 키는 그대로 `company_name`으로 직렬화된다. 전역 naming 전략은 없다. |
