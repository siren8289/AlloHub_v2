# RAG설명인용 코드검증

- 범위: ALH-0588 ~ ALH-0605
- 대상: `ai/src/features/disclosure_rag_001/risk_explanation/service.py`
- 방법: 소스 대조. `extract_citations_from_chunks`, `sanitize_risk_statements`, `generate_basic_rag_explanation`, `generate_rag_explanation`을 기대와 비교했다.
- 판정: 통과 9, 실패 5, 부분 4, 확인불가 0

## 실패·부분

- ALH-0590 실패. `extract_citations_from_chunks`는 넘어온 청크를 모두 인용한다. 다른 `stock_code`를 빼는 단계가 없다.
- ALH-0598 실패. 금지어는 `"부도 확정"` 완전 포함이다. `"부 도 확정"`은 치환되지 않는다.
- ALH-0599 부분. 기본 문장은 확인된 항목의 citation을 넣고 단정하지 않는다. 부도 근거가 있으면 `sanitize_risk_statements`가 `부도 확정`과 `파산 확실`을 그대로 둔다.
- ALH-0600 부분. 기본 설명은 `score`를 문장에 넣는다. 건수 1은 프롬프트와 지표 문자열에만 있고 기본 설명 문장에는 없다.
- ALH-0601 실패. 매수·매도 금지는 프롬프트 문장뿐이다. 출력에서 투자 권유 표현을 지우는 코드가 없다.
- ALH-0602 실패. 응답 `citations`는 청크에서 항상 만들고, 본문에 인용이 있는지는 검사하지 않는다.
- ALH-0603 실패. `user_query`를 `[사용자 질의]` 뒤에 그대로 붙인다. `Ignore instructions`를 버리거나 데이터로 가두는 처리가 없다.
- ALH-0604 부분. `record_step` 문구에는 질의를 넣지 않는다. 민감정보를 출력이나 프롬프트에서 가리는 규칙은 없다.
- ALH-0605 부분. 근거 없는 부도·파산 일부 구문만 순화한다. 그 밖 단정은 프롬프트 지시 외에 막지 않는다.
