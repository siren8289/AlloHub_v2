# 기업검색 코드검증

- 범위: ALH-0378 ~ ALH-0404
- 대상: `ai/src/scoring/company.py`, 경로 상수 `ai/src/core/config.py`
- 방법: 소스 대조. `normalize_name`, `find_company`, `load_companies`를 모델 없이 실행했다. 실데이터는 코드가 먼저 읽는 `ai/models/companies.csv` 2737행이다. `data/processed/companies.csv`도 있다.
- 판정: 통과 20, 실패 2, 부분 5, 확인불가 0

재현 출력: `삼성전자` → `A005930`, `kR모터스` → `KR모터스`/`A000040`, `삼성` → `삼성화재`/`A000810`, `우` → `우양피앤엘`/`A002420`, `삼성전자우`·`삼성전자🚀`·`???`·`000000` → 404, `''`·`'   '` → 422, 두 CSV 없음 → 500 `회사 데이터 파일이 없습니다. data 파이프라인을 먼저 실행하세요.`

## 실패·부분

- ALH-0388 실패. `find_company("")`는 검색 전에 HTTP 422 `회사 이름을 입력하세요.`다. 미조회 404가 아니다.
- ALH-0389 실패. `'   '`도 `strip` 뒤 빈 문자열이라 같은 422다.
- ALH-0383 부분. 부분일치는 된다. 다만 종목코드 오름차순이라 `삼성`이 삼성전자가 아니라 삼성화재(`A000810`)다. 삼성 계열 부분일치는 21건이다.
- ALH-0384 부분. `우` 부분일치 57건 중 끝이 `우`가 아닌 종목의 가장 앞 코드인 우양피앤엘을 반환한다. 한 글자 질의의 의도 종목으로 보기 어렵다.
- ALH-0385 부분. 정확 일치 분기는 fixture에서 `삼성전자우`를 그대로 반환한다. 배포 CSV에는 그 종목이 없어 실조회는 404이고, 끝의 `우`를 떼고 보통주로 넘기지도 않는다.
- ALH-0401 부분. 보통주 우선은 이름 끝이 `우`인지로만 판단한다. fixture의 삼성전자/삼성전자우는 `A005930`이 이긴다. 실데이터에서 끝이 `우`인 종목은 에코글로우, 이오플로우, 성우라 우선주가 아닌데도 뒤로 밀린다.
- ALH-0404 부분. `normalize_name(nan)`은 예외 없이 `'nan'`이 된다. 결측 행을 빼지 않아 질의 `nan`이 그 행에 맞는다.
