# DB저장조회 코드검증

- 범위: ALH-0338 ~ ALH-0357 (20건)
- 대상: 인용 파일은 `Allocation`이지만, 진단 케이스는 `CompanyScreen`·`ScreenService`·`CompanyScreenRepository`가 실제 계층이다. 배분은 `Allocation`·`AllocationLine`·`AllocationService`·`AllocationRepository`·`AllocationCalculator`, 저장소 설정은 `application.yml`·`compose.yaml`·`HealthController`다.
- 방법: 매핑·저장 순서·스키마 설정을 소스 대조. DB를 띄운 재시작 실험은 하지 않았다. 보존 여부는 설정으로 결정되는 건만 판정했다.
- 판정: 통과 17, 실패 1, 부분 2, 확인불가 0

## 실패·부분

- ALH-0347 실패. `Allocation.lines`는 `@OrderColumn`과 `@OrderBy`가 없는 `List`다. Hibernate 6.4 기본 `default_list_semantics`는 BAG라 순서를 저장하지 않는다. 재조회 SELECT에 순서 보장이 없다.
- ALH-0350 부분. `@ElementCollection`이라 JPA로 부모를 지우면 Hibernate가 `allocation_line`을 먼저 지운다. 다만 삭제 API가 없고, DB FK에 `ON DELETE CASCADE`도 없다.
- ALH-0356 부분. 틀린 비밀번호는 기동 로그의 Hikari 인증 예외로 보인다. `HealthController`는 DB를 보지 않고 항상 `status=ok`라, health로는 원인을 식별하지 못한다.

| ALH-0338 | P1 | 기업 진단 최초 ID | 통과 | 인용된 `Allocation`이 아니라 `CompanyScreen.id`가 `@GeneratedValue(IDENTITY)`다. `screenRepository.save`가 insert 때 id를 채운다. |

| ALH-0341 | P1 | 기업 위험 등급 저장 | 통과 | `ScreenService`가 `grade`를 `asText()`로 넣고 가공하지 않는다. `danger`가 다른 문자열로 바뀌지 않는다. |

| ALH-0343 | P1 | 회사명 Unicode | 통과 | `companyName`은 길이 제한 없는 `String`이다. H2·PostgreSQL 기본 문자셋이 UTF-8이라 한글과 괄호를 자르지 않는다. |
| ALH-0344 | P1 | 설명 최대 길이 | 통과 | `CompanyScreen.explanation`은 `@Column(length=2000)`이고 `ScreenService.cut`이 2000자를 넘기 전에 자른다. 2000자는 컬럼 안에 들어간다. 배분 설명도 같은 패턴이다. |
| ALH-0345 | P1 | 진단 재조회 정확성 | 통과 | POST 응답과 GET은 같은 `CompanyScreen` 컬럼이다. `get`은 `findById`이고 lazy 필드가 없어 저장값과 조회값이 같다. |
| ALH-0346 | P1 | 출자 기록 저장 | 통과 | `AllocationService`가 부모 1건과 `AllocationLine` 목록을 `setLines`한 뒤 `save` 한 번을 한다. `@CollectionTable(name="allocation_line")`이라 라인 3행이 된다. |
| ALH-0347 | P1 | 라인 순서 | 실패 | 리스트에 순서 컬럼이 없다. BAG라 저장 순서와 조회 순서가 보장되지 않는다. |
| ALH-0348 | P1 | 라인 금액 | 통과 | `AllocationCalculator.split`은 앞 사람을 버리고 마지막에 잔액을 준다. 101원의 50/50은 50원과 51원이다. `AllocationLine.amount`는 `long`이라 그 정수를 보존한다. |
| ALH-0349 | P1 | 라인 참조 무결성 | 통과 | 라인은 부모 `save` 안에서만 `allocation_id`로 들어간다. `@JoinColumn(name="allocation_id")`가 컬렉션 FK다. 독립 insert 경로가 없다. |
| ALH-0350 | P1 | 부모 삭제 시 라인 정책 | 부분 | 요소 컬렉션은 ORM 삭제 시 자식 행을 먼저 지운다. 서비스 삭제 메서드와 DB `ON DELETE CASCADE`는 없다. |
| ALH-0351 | P1 | 최근 진단 리스트 | 통과 | `CompanyScreenRepository.findTop10ByOrderByIdDesc`다. 11건이어도 id 기준 최신 10건이다. 인용 엔티티 `Allocation`의 쿼리가 아니다. |
| ALH-0352 | P1 | 최근 배분 리스트 | 통과 | `AllocationRepository.findTop10ByOrderByIdDesc`가 같은 상한과 정렬을 한다. |
| ALH-0353 | P1 | 동시 기록 저장 | 통과 | id는 DB `IDENTITY`와 PK다. 애플리케이션이 id를 만들지 않아 동시 10건도 PK가 중복되지 않는다. |
| ALH-0354 | P1 | 재시작 후 기록 | 통과 | `compose.yaml`의 `db-data`가 PostgreSQL 데이터 디렉터리를 유지한다. `ddl-auto`는 `update`라 재시작이 테이블을 비우지 않는다. |
| ALH-0355 | P1 | H2 메모리 모드 | 통과 | 로컬 `application.yml`은 `jdbc:h2:mem:allohub`다. `DB_CLOSE_DELAY`가 없어 프로세스 재시작 시 메모리 DB는 비워진다. |
| ALH-0356 | P1 | DB 인증 오류 | 부분 | 틀린 비밀번호는 풀 초기화 실패 로그로 남는다. `/api/health`는 연결 확인 없이 `ok`만 반환한다. |
| ALH-0357 | P1 | DB 트랜잭션 롤백 | 통과 | AI 호출은 `save` 앞이다. `SimpleJpaRepository.save`가 `@Transactional`이라 부모 insert와 `allocation_line` insert가 한 트랜잭션에서 flush된다. save 실패 시 둘 다 롤백된다. 서비스 클래스 자체에는 `@Transactional`이 없다. |
