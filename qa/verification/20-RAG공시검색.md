# RAG공시검색 코드검증

- 범위: ALH-0522 ~ ALH-0563, ALH-0885, ALH-0886
- 대상: `ai/src/features/disclosure_rag_001/disclosure_search/service.py`, `schemas.py`의 `SearchQuery`, `compose.yaml`
- 방법: 소스 대조. 회사·기준일 분기는 코드가 결정적이라 실DB 없이 판정했다. pytest는 의존성 미설치로 실행하지 않았다.
- 판정: 통과 39, 실패 4, 부분 1, 확인불가 0

## 실패·부분

- ALH-0561 부분. SQL은 `stock_code`와 `rcept_dt <= as_of_date`를 건다. 그러나 행이 있으면 점수 네 개를 전부 1.0으로 채우고, 행이 없으면 `None`을 돌려 메모리 검색으로 떨어진다.
- ALH-0562 실패. `SearchFilter.report_types`는 스키마에만 있다. `search_disclosures_with_filter`와 pgvector SQL 모두 보고서 유형을 거르지 않는다.
- ALH-0563 실패. `as_of_date`는 형식 없는 문자열이다. `20260231`은 422가 아니고 문자열 비교와 `int()`에 그대로 들어간다.
- ALH-0885 실패. `005930`과 `A005930`을 같은 형태로 바꾸는 함수가 없다. 코퍼스와 `companies.csv`는 `A005930`인데 검색은 문자열 완전 일치만 한다. 화면 스키마 예시는 `005930`이다.
- ALH-0886 실패. `compose.yaml`의 DB 이미지는 `postgres:16-alpine`이고 pgvector 확장 설치가 없다. AI 서비스에도 `DATABASE_URL`이 없다. 연결 실패는 `except Exception: pass` 뒤 메모리 결과로 바뀌어, 벡터 검색 불가를 성공 검색과 응답에서 구분하지 않는다.
