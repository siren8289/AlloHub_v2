# 데이터품질운영 코드검증

- 범위: ALH-0761 ~ ALH-0776 (16건)
- 대상: `data/etl/run.py`, `data/etl/load.py`, `data/etl/fetch.py`, `data/etl/transform.py`. 없는 CSV와 재로딩은 힌트 밖인 `ai/train/common.py`, `ai/src/scoring/company.py`를 봤다.
- 방법: 소스 대조. 저장 인코딩과 선행 0은 pandas로 확인했다. `python -m data.etl.run`과 공개 API는 실행하지 않았다.
- 판정: 통과 4, 실패 7, 부분 5, 확인불가 0

## 실패·부분

- ALH-0763 실패. `to_csv`에 인코딩을 넘기지 않는다. pandas는 `None`을 `utf-8`로 쓰고 BOM이 있는 UTF-8-SIG가 아니다.
- ALH-0764 실패. 공시 조회가 예외로 끝나면 `companies.csv`는 갱신되지 않지만, 그 전에 `krx_listed.csv`와 이미 받은 공시 CSV는 저장된다. 완전성 알림이 없고, 성공 코드의 빈 공시는 0건으로 회사 표를 만든다.
- ALH-0765 부분. 고른 기준일은 콘솔에만 찍힌다. CSV `bas_dt`는 각 상장 행의 `basDt`가 있을 때만 채워지고, 수집 시각은 없다.
- ALH-0766 실패. 현재 상장 행에 법인별 최신 배당을 그대로 붙인다. 상장일과 배당일의 차이 검증이나 설명 컬럼이 없다.
- ALH-0767 실패. 같은 공시가 두 번 있으면 `count_by_crno`가 둘 다 센다. 부풀림을 감지하지 않는다.
- ALH-0768 부분. 전처리와 CSV 원문은 문자 13자리를 유지한다. `ai/train/common.py`의 `read_csv`는 dtype이 없어 `0123456789012`를 다시 읽으면 `123456789012`가 된다. API 로더 `company.py`만 `dtype=str`이다.
- ALH-0769 부분. `"005930"`은 CSV에 `005930`으로 남는다. dtype 없는 학습용 `read_csv`는 이를 `5930`으로 읽는다.
- ALH-0770 실패. `run.py`는 위험 라벨 건수만 출력한다. 약 8% 점검이 없고, 학습 지표에도 recall이 없다.
- ALH-0771 실패. API 이름, URL, 기준일, 수집 시각을 재현용 메타데이터로 남기지 않는다. 기준일은 로그 한 줄이다.
- ALH-0772 부분. `README.md`는 공공누리 제4유형(출처표시, 상업적 이용금지, 변경금지)을 적는다. ETL 산출물에는 이용조건이 없고, 화면 고지는 출처와 참고값만 있다.
- ALH-0773 실패. 첨부 두 필드와 중첩 객체만 버리고 나머지 값은 300자까지 원본 CSV에 넣는다. 개인정보 판별이나 마스킹이 없다.
- ALH-0776 부분. 저장 전에 수집이 실패하면 기존 `companies.csv`는 남는다. 보존 정책은 없고 `to_csv`가 대상 경로에 직접 써 쓰는 도중 실패하면 파일이 잘릴 수 있다.
