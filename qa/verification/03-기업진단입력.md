# 기업진단입력 코드검증

- 범위: ALH-0022 ~ ALH-0051 (30건)
- 대상: `front/src/pages/ScreenPage.tsx`, `front/src/api/api.ts`, `back/src/main/java/com/allohub/screen/controller/ScreenController.java`, `back/src/main/java/com/allohub/screen/dto/ScreenRequest.java`, `back/src/main/java/com/allohub/screen/service/ScreenService.java`, `back/src/main/java/com/allohub/ai/AiClient.java`, `ai/src/api/schemas.py`, `ai/src/api/routes.py`, `ai/src/scoring/company.py`
- 방법: 소스 대조. 브라우저 실행 없음.
- 판정: 통과 26, 실패 1, 부분 3, 확인불가 0

## 실패·부분

- ALH-0028 부분. `삼성`은 존재 기업으로 처리되어 결과로 가지만, `find_company`가 부분 일치 여러 건 중 종목코드가 가장 빠른 한 곳(데이터상 삼성화재)만 고른다. 다른 삼성을 고르는 단계가 없다.
- ALH-0035 부분. 101자는 프론트와 Spring `ScreenRequest`를 그대로 통과한다. AI Pydantic `max_length=100`이 422로 막아 길이 제한 우회(절단 후 진단)는 없다. 그러나 `AiClient.screen`은 404만 `notFound`로 두고 422는 502 `AI 서버 호출에 실패했습니다.`로 바꾼다.
- ALH-0040 부분. 1000자도 ALH-0035와 같은 경로다. 진단은 되지 않지만 검증 실패가 4xx와 길이 사유로 내려오지 않는다.
- ALH-0051 실패. Enter로 진단을 시작하지 않는다. `type="button"`이라 입력 중 Enter가 제출 이벤트가 되지 않는다.
