# 모델학습검증 코드검증

- 범위: ALH-0777 ~ ALH-0792 (16건)
- 대상: `ai/train/train_ml.py`, `ai/train/train_dl.py`, `ai/train/common.py`, `ai/src/scoring/features.py`. 캐시와 확률 안내는 `ai/src/inference/ml_risk.py`, `ai/src/inference/dl_risk.py`, `ai/src/llm/explainer.py`, `ai/src/llm/prompts.py`. 노트북은 `notebook/model_evaluation.ipynb`.
- 방법: 소스 대조. 케이스 힌트는 모두 `train_ml.py`지만 DL 저장은 `train_dl.py`, 컬럼 정의는 `features.py`에 있다. 학습은 시작하지 않았다.
- 판정: 통과 10, 실패 2, 부분 4, 확인불가 0

## 실패·부분

- ALH-0784 부분. 이진 `f1`은 저장한다. 양성 recall은 `metrics_ml.json`과 `metrics_dl.json`에 없다. 불균형 보정은 ML `class_weight="balanced"`, DL `pos_weight`뿐이다.
- ALH-0785 실패. 지표는 행 수, 위험 행 수, accuracy, f1, roc_auc만 저장한다. 데이터 해시, 기준일, 학습 버전이 없어 CSV를 바꿔도 어떤 데이터로 학습했는지 남지 않는다.
- ALH-0786 부분. 샘플 1개면 `train_test_split(..., stratify=y)`가 sklearn `ValueError`로 죽는다. 행 수 부족을 설명하는 자체 검사는 없다.
- ALH-0787 실패. 전부 `distress=0`이면 분할은 될 수 있다. ML은 `predict_proba(...)[:, 1]`이라 클래스가 하나면 `IndexError`다. DL은 `roc_auc_score`가 단일 클래스에서 예외를 낸다. 둘 다 막지 않는다.
- ALH-0788 부분. `load_ml_model`과 `load_dl_model`에 `force_reload`가 있지만 `predict_ml`과 `predict_dl`은 기본값으로만 호출한다. 프로세스가 살아있는 동안 파일을 바꿔도 옛 모델이 남고, 프로세스를 다시 띄울 때만 새 파일을 읽는다.
- ALH-0792 부분. 학습 코드는 확률을 점수 지표로만 저장한다. `basic_explanation`과 화면 하단은 참고값이라고 적는다. Gemini 경로는 모델 문장을 그대로 반환하고, 프롬프트는 투자 권유 금지만 있어 미검증 확률을 확정이 아니라고 강제하지 않는다.
